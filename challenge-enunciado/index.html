1.2. CHALLENGE DE APRENDIZAJE

NestJS + React Native

Prueba práctica · Del backend a la pantalla

ORIENTACIÓN · ANTES DE EMPEZAR

Una aplicación que crece contigo

Esta prueba evalúa si sabes conectar y hacer avanzar un pequeño sistema Full Stack. Partirás de una comunicación sencilla entre NestJS y React Native y, si avanzas, incorporarás parámetros de ruta, separación Controller–Service y lógica de negocio.

No son tres ejercicios independientes. Cada nivel amplía el anterior. Para alcanzar 7 puntos debe funcionar también el nivel de 5; para alcanzar 10 deben funcionar los tres.

Condiciones de trabajoPrueba sin Internet · Proyecto proporcionado y ya configurado · Trabaja únicamente sobre ese proyecto · No basta con escribir código: debes poder demostrar que funciona.
CHALLENGE 1 hasta 5 CHALLENGE 2 hasta 7 CHALLENGE 3 hasta 10
01CONEXIÓN BÁSICA
HASTA 5 / 10

Primera meta: demostrar la comunicación Backend → Frontend

Qué estás demostrando: que React Native puede pedir información a NestJS, recibirla, guardarla y representarla en pantalla.

Antes de programar, piensa en el recorrido:¿Quién crea el dato? NestJS. ¿Quién lo solicita? React Native. ¿Qué viaja entre ambos? Una respuesta HTTP con datos JSON.

BACKEND · NestJS

Crea un endpoint GET en un Controller que devuelva tu nombre mediante una respuesta JSON.

La respuesta debe contener tu propio nombre. Ese dato será la evidencia sencilla que utilizaremos para comprobar que la comunicación es real.

FRONTEND · React Native

  1. Al abrir la aplicación, realiza automáticamente la petición al endpoint.
  2. Convierte la respuesta recibida en datos utilizables.
  3. Guarda el dato recibido en el estado de React.
  4. Muestra tu nombre en la interfaz.
NestJS → GET → HTTP → React Native → estado → interfaz
CHECKPOINT · PUEDES AVANZAR SI…

Al abrir la app aparece tu nombre y puedes explicar este recorrido: NestJS → petición HTTP → JSON → estado → pantalla. Si cambias el nombre en el backend, el cambio debe llegar al frontend. No es válido escribir el nombre directamente en React Native.

02PATH PARAM + SERVICE
HASTA 7 / 10

Segunda meta: utilizar un ID para recuperar un recurso concreto

Qué estás demostrando: que comprendes un Path Param y sabes separar la entrada HTTP de la búsqueda de datos mediante Controller y Service.

Nuevo reto mental:React Native ya no pide siempre el mismo dato. El usuario elige un ID y ese valor debe viajar por la URL hasta NestJS.

BACKEND · NestJS

Utiliza exactamente esta pequeña colección de prueba:

1 → Ana · DAM2 → Marcos · DAW3 → Lucía · DAM

Permite consultar un alumno concreto mediante:

GET /alumnos/1
GET /alumnos/2
GET /alumnos/3

El Controller recupera el identificador mediante un Path Param y delega en un Service. El Service busca y devuelve el alumno.

La colección y la búsqueda no deben quedar resueltas directamente en el Controller.

FRONTEND · React Native

Añade una forma sencilla de introducir un ID, un botón BUSCAR ALUMNO y una zona visual donde mostrar el alumno recibido.

Cambiar el ID debe permitir recuperar otro alumno desde NestJS.

ID → GET /alumnos/:id → @Param → Controller → Service → JSON → React Native
CHECKPOINT · PUEDES AVANZAR SI…

Escribes 1, 2 o 3 en React Native y obtienes el alumno correspondiente. Debes poder explicar: ID → URL → @Param → Controller → Service → alumno → JSON → interfaz.

03LÓGICA EN SERVICE
HASTA 10 / 10

Tercera meta: hacer que el Service transforme información

Qué estás demostrando: que el backend no solo devuelve datos; también puede aplicar una regla y devolver información nueva derivada de ellos.

Decisión arquitectónica:El Controller recibe la petición y delega. La interpretación del curso pertenece al Service.

BACKEND · NestJS

Añade una consulta:

GET /alumnos/:id/nivel

El Controller recupera el ID y delega. El Service localiza al alumno y aplica la lógica necesaria para interpretar su curso/especialidad.

Ejemplo de lógica
DAM → Desarrollo de aplicaciones
DAW → Desarrollo web

La lógica de interpretación no debe estar en el Controller.

FRONTEND · React Native

Reutiliza el ID del alumno y añade una acción CONSULTAR NIVEL. Recibe el objeto del backend y presenta el resultado de forma clara y visual.

Puedes mostrar nombre, curso, especialidad y un mensaje personalizado.

GET /alumnos/:id/nivel → Controller → Service → lógica → JSON → React Native
CHECKPOINT · NIVEL 10 CONSEGUIDO SI…

Con un ID válido recuperas al alumno, el Service genera correctamente su especialidad y React Native muestra los datos recibidos. Debes poder señalar dónde está la lógica y explicar por qué no la has colocado en el Controller.
